# 도면 사진(비상대피도) → 복도·방 초안: 예전(이진화) vs 새(영역 분할)

재현: `python experiments/plan_import/run.py [출력폴더]` (합성 16장 + 실제 사진 1장, 약 40초, CPU)

## 결론
- 합성 대피도 사진 16장: **복도 IoU 0.52 → 0.92**, 헛것(정답에 없는 방) 평균 **8.1 → 1.3개**, 방 IoU 0.92 → 0.93 (원래 높았음).
  문 찾음 95% (새로 생김, 예전 방식은 문을 안 만듦). 한 장 1.1초 (예전 0.2초).
- **실제 학생회관 지하 대피도 사진**: 예전 방식은 조각 58개(복도가 방들과 한 덩어리, 방은 글자 줄에서 반으로 갈림),
  새 방식은 **복도 1개(박스 3개) + 방 22개, 문 9개**. 눈으로 보면 번호 있는 방 19개 중 16개가 맞는 박스,
  나머지(33B18·33B19·33B115)는 빠지거나 작게 잡힘 → 공간 탭에서 "클릭해서 영역 추가"·직접 그리기로 보충.
- ㄱ·T 자 복도는 박스 여러 개로 나눠지고 박스끼리 통로(문)로 이어짐.

## 합성 생성기 (`src/indoorgs/space/plan_synth.py`)
- 배치 4개: `long`(긴 복도 양쪽 방), `L`(ㄱ자 복도), `T`(T자 복도), `hall`(학생회관 지하 흉내: 넓은 가로 복도, 위로 계단실, 아래 X 빗금 칸)
- 그림 2종: `thin` = 실제 사진처럼 크림색 바탕, 올리브색 가는 이중선 벽, 복도 색 없음, 빨간 화살표·현위치·소화기, 문 호, X 빗금, 계단 사선 /
  `thick` = 굵고 어두운 벽, 복도 색칠, 초록 화살표
- 공통: 방 번호 글자, 거리 글자(14m 등), 파란 제목 띠, 빨간 테두리, 안쪽 테두리선 안 범례 상자·행동요령 상자
- 사진: 아래에서 비스듬히(원근), 따뜻한 조명 기울기, 흐림, 잡음, JPEG 75, 옆에 빨간 종이·다른 안내문, 위 그림자 띠
- 네 점 = 사진 속 안쪽 테두리선 모서리 + 클릭 오차 ±3px. 정답 = 방·복도 안쪽 마스크 (0.05 m 칸)
- 한계: 이 PC 에 한글 글꼴이 없어 글자는 영문(HERE, B101)

- IoU: 정답 방·복도마다 가장 많이 겹친 찾은 항목(새 방식은 한 영역의 박스 합집합, 예전은 다각형 하나), 1:1 짝.
- 예전 방식 "방 IoU" 가 높아 보이는 건 헛조각이 많아도 짝 하나만 보기 때문. 복도는 화살표·글자에 막혀 조각나거나 방과 붙음.
- thin 복도 0.86~0.88: 문 틈 닫기가 벽 두께 안쪽 반을 먹어 복도가 조금 좁게 나옴 (모두 같은 방향 오차).

## 방법 (새)
`src/indoorgs/space/plan_segment.py` 머리말 참고. 요약: 조명 고르기 → 잉크(종이보다 어두움, 빨강·초록 화살표·기호 제외,
긴 색 선 가장자리 제외) → 글자 지우기(긴 가로·세로 선 근처만 남기고, 나머지는 가는 선·긴 사선만) → 문 틈 닫기(가로·세로 1.2 m)
→ 빈 공간 덩어리 → 건물 밖(가장 큰 벽 덩어리 윤곽 밖)·빗금(비스듬한 윤곽)·좁은 틈 버림 → 복도 = 가늘고 긴 덩어리,
색칠 복도면 Lab 색으로 고르고 벽 없이 붙은 다른 색은 나눔 → 가장 큰 직사각형을 차례로 뽑아 박스 → 마주 보는 박스 사이 띠에서
잉크 없는 0.5~2.5 m 구간 = 문 → 믿음 = (벽으로 둘러싸인 정도 + 박스가 영역을 채우는 정도)/2.
